请为受管发布流程交付一套离线模型检查器。每份虚构制品有不可变摘要和密级；系统的可变状态只有活动制品版本、策略版本、已登记审批、已撤回审批及当前发布槽。输入是一份初态和至多 20 个带唯一 ID 的事件（登记审批、撤回、改策略、置换制品、发布申请），事件有偏序先后关系，互不依赖的事件允许任意顺序。审批绑定制品摘要、策略代次、槽及逻辑序号窗口。进程按顺序处理每个事件，首事件序号为 1；撤回允许先于登记，且后来的登记不能清除撤回标记。策略规定每个槽最高密级、必须各有一份审批的组织集合，以及不同组织必须由不同人出具审批。发布事件使用申请中明确引用的审批，执行时必须重核所有绑定和值域，被拒绝只产生回执。初态可声明已发布槽；改策略或撤回后若槽中制品不再满足当前活跃政策，槽必须在同一事件内撤下。审批窗口只用于判断申请时能否消费该审批，发布后窗口自然届满不触发撤下。重新换回旧策略或旧制品不恢复已撤下的发布。
check 枚举所有尊重偏序的执行，同时验证给定不变式：任何可见槽均满足当前级别政策，任何两个槽不得同时发布同一排他组的不同制品，任何必发申请（输入有标记）在所有合法顺序都需要得到允许回执。前一类跨槽排他条件作为检查目标，不由各单槽发布前置校验自动拒绝。输出每条不变式的最短失败事件前缀，同长按事件 ID 序列排最小，并附逐步快照；全部通过给达成的不同最终状态数。compare 对比两套政策的最小结果分歧前缀。状态合并必须保留已执行事件集合和对未来有影响的审批、撤回与已发布槽来源。禁止逐一展开所有完整排列。测试覆盖提交集合相同但顺序结果不同、同一审批撤回两次、撤回和发布竞争、改策略后原子撤下、状态合并误剪及小规模排列对拍。

交付可复现事件偏序和检查结果的样例，样例及夹具均用本地虚构数据。实现从空仓库开始，在 Windows 原生 Python 3.12 环境用标准库和 CPU 运行。验证入口是 `python -m solution <命令> CASE.json`，处理持久状态的命令还需 `--db DB.sqlite`。标准输出的 UTF-8 JSON 结果对相同逻辑输入必须一致，结构错误同时报告错误码和字段位置。README 列全输入输出定义与复现命令，断言测试用 `python -m unittest discover -s tests -v` 执行。
